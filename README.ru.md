# LayoutSwitch

[English](README.md) | **Русский**

Небольшое приложение для macOS, которое переключает раскладку по **Ctrl + Shift** или любому из настроенных сочетаний. Живёт в строке меню, работает в фоне и не требует Xcode для сборки.

## Установка через Homebrew

Если [Homebrew](https://brew.sh/) уже установлен, выполните:

```sh
brew tap lukdut/layoutswitch https://github.com/lukdut/LayoutSwitch.git
brew install --cask lukdut/layoutswitch/layoutswitch
```

Этот репозиторий также служит Homebrew tap. В первой команде нужен полный URL. Cask устанавливает опубликованную сборку для **Apple Silicon (arm64)** и **macOS 13 или новее** в `/Applications` и проверяет SHA-256 архива.

Homebrew устанавливает тот же релиз с локальной подписью. При первом запуске может потребоваться **«Всё равно открыть»** в разделе **Системные настройки → Конфиденциальность и безопасность**, а затем разрешение на **Мониторинг ввода**. Нотарификации Apple у приложения пока нет.

Если LayoutSwitch уже установлен вручную, завершите приложение и перенесите старый `LayoutSwitch.app` из «Программ» перед установкой через Homebrew. Настройки приложения хранятся отдельно и сохранятся.

Обновление после добавления новой версии в cask:

```sh
brew update
brew upgrade --cask lukdut/layoutswitch/layoutswitch
```

## Установка готового приложения

Скачайте [LayoutSwitch 1.1.0 для Apple Silicon](https://github.com/lukdut/LayoutSwitch/releases/download/v1.1.0/LayoutSwitch-1.1.0-macos-arm64.zip) со [страницы релиза](https://github.com/lukdut/LayoutSwitch/releases/tag/v1.1.0), распакуйте архив и перенесите `LayoutSwitch.app` в `/Applications` («Программы»). Нужна macOS 13 или новее. Интерфейс приложения в версии 1.1.0 — на русском языке.

Готовая сборка предназначена для **Apple Silicon (arm64)**. Для Intel соберите приложение из исходников на своём Mac по инструкции ниже. В релизе также есть `SHA256SUMS.txt` для проверки архива:

```sh
shasum -a 256 -c SHA256SUMS.txt
```

Запустите команду в директории, куда скачаны архив и файл контрольных сумм.

Приложение подписано локальной подписью ad hoc и не нотарифицировано Apple. Если macOS блокирует первый запуск, следуйте [инструкции Apple по открытию приложений](https://support.apple.com/ru-ru/102445), только если доверяете скачанному файлу. После запуска разрешите мониторинг ввода, как описано ниже.

## Сборка из исходников

Требования: macOS 13 или новее для приложения и Swift 6.0 или новее для сборки и тестов (Xcode 16+ / совместимые Command Line Tools). Если инструментов нет, установите их командой `xcode-select --install`.

В директории `LayoutSwitch` выполните:

```sh
./scripts/build.sh
open dist/LayoutSwitch.app
```

Готовое приложение находится в `dist/LayoutSwitch.app`. Для постоянного использования сначала перенесите его в `/Applications` («Программы»), затем открывайте именно эту копию. Сборка создаётся для архитектуры текущего Mac. Зависимостей из интернета нет.

## Первый запуск

1. Нажмите **«Запросить доступ»** в окне настроек.
2. В macOS откройте **Системные настройки → Конфиденциальность и безопасность → Мониторинг ввода** и включите **LayoutSwitch**. Кнопка **«Открыть настройки macOS»** ведёт в этот раздел. Если приложения нет в списке, добавьте `.app` кнопкой «+».
3. Если macOS предложит завершить приложение, завершите и откройте его снова. При необходимости используйте **«Повторить подключение»**.
4. Убедитесь, что выбраны хотя бы две раскладки. Нажмите **Ctrl + Shift** и отпустите любую из этих клавиш в обычном текстовом поле.

Разрешение выдаётся пользователем в системных настройках. Приложение использует пассивное наблюдение и не запрашивает «Универсальный доступ».

### Мониторинг ввода после обновления

Локальная подпись меняется при пересборке приложения. macOS может потребовать разрешение заново, даже если LayoutSwitch уже включён в «Мониторинге ввода». Если завершение и повторный запуск приложения не помогают:

1. Завершите LayoutSwitch через его меню в строке меню.
2. В **Системные настройки → Конфиденциальность и безопасность → Мониторинг ввода** выберите **LayoutSwitch** и удалите его запись кнопкой «−».
3. Добавьте `/Applications/LayoutSwitch.app` кнопкой «+» и включите доступ.
4. Запустите LayoutSwitch; если macOS попросит перезапуск, завершите и откройте приложение снова.

## Возможности

- **Несколько сочетаний.** Нажмите «Добавить сочетание…», зажмите сочетание и отпустите все клавиши. Каждое сочетание переключает выбранные раскладки по одному и тому же кругу. Отдельные записи можно изменить кнопкой «Изменить…» или удалить кнопкой с корзиной. Дубликаты не сохраняются; в списке должно остаться хотя бы одно сочетание. «Оставить только Ctrl + Shift» сбрасывает список. Поддерживаются два–четыре модификатора из Ctrl, Shift, Option, Command либо один–четыре модификатора с одной обычной клавишей. Esc отменяет запись. Потеря фокуса окна также отменяет запись.
- **Любая сторона клавиатуры.** Левые и правые Ctrl/Shift/Option/Command равнозначны; можно смешивать стороны.
- **Выбор раскладок.** Переключение по кругу между отмеченными источниками ввода. Цифры справа показывают порядок. «Все раскладки» также автоматически включает новые источники, добавленные в macOS.
- **Пауза.** В меню приложения или переключателем в настройках. Ручная команда «Следующая раскладка» остаётся доступна на паузе.
- **Автозапуск.** Включается отдельно через «Запускать при входе в macOS». Состояние считывается из системы; при необходимости приложение предлагает открыть системное подтверждение.
- **Текущая раскладка.** Отображается в строке меню и обновляется при переключении средствами macOS.
- **Сохранение настроек.** Список сочетаний, выбранные раскладки и пауза сохраняются в UserDefaults приложения (`local.masos.LayoutSwitch`). При обновлении ранее сохранённое сочетание автоматически становится первой записью списка.

## Правила срабатывания

| Действие | Результат |
| --- | --- |
| Ctrl, затем Shift; отпустить любую из этих клавиш | Одно переключение сразу при отпускании; отпускание оставшейся клавиши не переключает повторно |
| Shift, затем Ctrl; отпустить в любом порядке | То же самое |
| Удерживать Alt (Option) и несколько раз нажать и отпустить Shift при настроенном Alt + Shift | Переключение при каждом отпускании Shift; так же работает удержание Shift и повторное нажатие Alt |
| Удерживать Ctrl + Shift | Переключения до отпускания нет |
| Ctrl + Shift + буква | Переключения нет; сочетание получает приложение |
| Зажать Ctrl + Shift, отпустить Ctrl, затем нажать букву, удерживая Shift | Раскладка уже переключилась при отпускании Ctrl; буква не вызывает повторного переключения |
| Добавить Option, Command или Fn до отпускания клавиши сочетания | Переключения нет, если модификатор не входит в настройку |
| Щёлкнуть мышью, перетаскивать или прокручивать до отпускания клавиши сочетания | Переключения нет |
| Настроить Ctrl + Option + Space | Одно переключение при отпускании Ctrl, Option или Space; повторное нажатие и отпускание при удержании остальных клавиш переключает снова |
| Включить приложение с уже зажатыми клавишами | Сначала нужно отпустить их; переключение возможно со следующего нажатия |

Если сочетания пересекаются, например Ctrl + Shift и Ctrl + Shift + Space, полное нажатие большего сочетания переключает раскладку один раз. Отпускание оставшихся клавиш не запускает меньшее сочетание. После успешного переключения можно использовать другое настроенное сочетание, удерживая общий модификатор.

Для повторного переключения достаточно снова зажать полное сочетание и отпустить любую его клавишу. После отменённого сочетания нужно отпустить все клавиши перед следующей попыткой. Посторонняя клавиша или действие мышью после переключения также блокируют дальнейшие переключения до полного отпускания. Нажатия не поглощаются глобально. Если настроить сочетание с обычной клавишей, активное приложение тоже получит его — выбирайте свободное сочетание. Буквы при записи обозначают **физические позиции английской клавиатуры**, независимо от активного языка.

Caps Lock и Fn не назначаются в качестве сочетания. Уже включённый Caps Lock не мешает работе; нажатие Caps Lock до отпускания клавиши сочетания отменяет переключение. F1–F16 можно записать, если клавиатура отправляет обычные F-клавиши без удержания Fn; мультимедийные клавиши не поддерживаются.

## Ограничения macOS

- **Secure Input.** При защищённом вводе наблюдение может быть недоступно, например с Secure Keyboard Entry в Terminal. Приложение показывает это состояние и возобновляет работу после его окончания. Сохраните штатное системное сочетание как запасное.
- **Сложные методы ввода.** Выбираются включённые и доступные для выбора источники, включая режимы IME. Составление китайского/японского символа лучше завершить до переключения: поведение незавершённой композиции зависит от метода ввода и версии macOS. Отдельной обработки композиции в этой версии нет.
- **Конфликт системных сочетаний.** Зарезервированное macOS сочетание может выполнить системное действие или не попасть в приложение. При записи выберите другое.
- **Локальная подпись.** По умолчанию `.app` подписывается ad hoc для локального использования. Для стабильного доверия между пересборками можно передать `CODESIGN_IDENTITY="имя вашего сертификата" ./scripts/build.sh`. После пересборки, переноса или смены подписи macOS может потребовать повторную выдачу разрешения. Скрипт не выполняет подпись Developer ID и нотарификацию автоматически. Готовый архив 1.1.0 также использует подпись ad hoc.
- **Одна запущенная копия.** Второй процесс с тем же bundle ID завершается, чтобы одно нажатие не вызывало два переключения.

## Проверки и разработка

```sh
# Тесты распознавания, записи сочетания и выбора следующей раскладки
./scripts/swift.sh test

# Отладочная сборка
./scripts/swift.sh build

# Сборка .app с оптимизацией, иконкой и локальной подписью
./scripts/build.sh

# Диагностика без запроса разрешения и без переключения раскладки
dist/LayoutSwitch.app/Contents/MacOS/LayoutSwitch --diagnose
```

Диагностика выводит JSON: версию приложения и диагностики, доступность мониторинга ввода для этого процесса, состояние Secure Input, текущий источник и список доступных источников. Для проверки глобального сочетания запускайте `.app`: запуск бинарника из Terminal может иметь другой контекст разрешений macOS.

Чтобы собрать отчёт для отправки, запустите `scripts/collect-diagnostics.command` (в архиве сборки — «Собрать диагностику.command»). Файл `LayoutSwitch-diagnostics-…txt` появится на рабочем столе. Он содержит версию приложения из `/Applications`, диагностический снимок и системный журнал за последний час. Даже если событий в журнале нет, сведения о версии останутся в отчёте.

Если переключение по сочетанию занимает от 100 мс после вызвавшего его отпускания клавиши, приложение записывает в системный журнал длительность доставки события (`delivery`), ожидания обработки (`queue`) и выполнения переключения (`switch`). Следующая запись `Switch phases` уточняет, на что ушло время внутри `switch`: чтение текущего источника (`readCurrent`), проверка доступности и выбор следующего (`prepare`), системный вызов выбора (`select`), проверка результата или обновление кэша после ошибки (`confirm`) и обновление интерфейса LayoutSwitch (`publish`). Посмотреть такие записи за последние 10 минут:

```sh
/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "local.masos.LayoutSwitch" AND category == "SwitchLatency"'
```

Журнал содержит длительности и причины прерывания мониторинга, без текста и кодов клавиш. Изменения состояния мониторинга записываются в категорию `Monitoring` того же subsystem: она помогает отличить задержку от паузы из-за разрешений или Secure Input. Замер заканчивается после вызова переключения и обновления индикатора LayoutSwitch; применение раскладки другим приложением может завершиться позднее.

Если сочетание совсем не сработало, посмотрите все категории:

```sh
/usr/bin/log show --last 10m --style compact --predicate 'subsystem == "local.masos.LayoutSwitch"'
```

Категория `Shortcut` записывает распознавание сочетания, отмену и результат выбора раскладки. Причины отмены: `otherKey` — другая клавиша, в том числе ещё не отпущенная перед сочетанием; `extraModifier` — лишний модификатор; `pointerAction` — кнопка мыши; `otherAction` — например, прокрутка; `unexpectedKeyRelease` — отпускание без полученного события нажатия; `heldAtReset` — клавиши или кнопки были зажаты при запуске или сбросе мониторинга. Отдельно записывается отмена уже распознанного сочетания при изменении состояния мониторинга.

Результат `confirmed` означает, что после системного вызова прочитана ожидаемая раскладка; `unconfirmed` — вызов вернул успех, но текущий источник пока не совпал с ожидаемым; `failed` — системная ошибка; `unavailable` — нет следующего доступного источника. `unconfirmed` сам по себе не доказывает отказ: раскладка может измениться позднее. Обычный набор текста не создаёт записей о сочетании.

Все кэши сборки находятся в `.build`. Обёртка `scripts/swift.sh` отключает вложенную песочницу SwiftPM для работы из ограниченных сред разработки. В пакете нет внешних зависимостей, плагинов и сетевых запросов.

При каждом релизе обновляйте `version` и `sha256` в `Casks/layoutswitch.rb` по опубликованному архиву. Homebrew использует эту версию для обновлений.

### Устройство

```text
Sources/ShortcutCore/       распознавание и запись сочетаний, выбор следующего источника
Sources/LayoutSwitch/      CGEventTap, TIS, настройки, SwiftUI и приложение в строке меню
Tests/ShortcutCoreTests/   тесты без глобального ввода и системных разрешений
Tests/LayoutSwitchTests/   тесты кэша раскладок и переключения с подменой системного API
Casks/layoutswitch.rb     установка через Homebrew из GitHub Releases
Resources/Info.plist       настройки .app
scripts/                  сборка и генерация иконки через AppKit
dist/LayoutSwitch.app     результат сборки (не включается в git)
```

`CGEventTap` с `.listenOnly` получает флаги, коды клавиш и действия мышью на главном run loop. Состояние распознавания отделено от AppKit и TIS. Переключение откладывается за пределы callback события через common modes run loop, которые также обслуживаются при открытом меню. При отключении tap, сне, смене сеанса или Secure Input незавершённое сочетание сбрасывается.

`TISSelectInputSource` выбирает источник напрямую. Список раскладок и их системные объекты кэшируются и обновляются при изменении доступных источников, активации приложения, пробуждении или ручном обновлении. Обычное переключение читает текущий источник и проверяет доступность выбранных раскладок без повторного получения всего списка. При нехватке источников, недоступной раскладке или ошибке выбора кэш обновляется. Уведомление о смене текущей раскладки обновляет только текущий источник; неизвестный источник вызывает обновление списка. Если доступно меньше двух отмеченных источников, приложение не подменяет выбор пользователя другими раскладками.

Разрешение проверяется через [CGPreflightListenEventAccess](https://developer.apple.com/documentation/coregraphics/cgpreflightlisteneventaccess()) и запрашивается через [CGRequestListenEventAccess](https://developer.apple.com/documentation/coregraphics/cgrequestlisteneventaccess()). Автозапуск использует [SMAppService.mainApp](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp) и [register()](https://developer.apple.com/documentation/servicemanagement/smappservice/register()). Описание TIS также доступно в `TextInputSources.h` локального macOS SDK.

Приложение не получает текст через события клавиатуры и не отправляет данные в сеть. Диагностический журнал содержит только результаты обработки настроенного сочетания, причины отмены, системные коды ошибок и длительности. Текст и коды нажатых клавиш не записываются; в памяти во время жеста хранятся коды зажатых клавиш и состояние модификаторов.

### Проверка вручную

1. Разрешить Input Monitoring и проверить Ctrl + Shift в TextEdit с русской и английской раскладками, с обеими сторонами клавиатуры и разным порядком нажатия/отпускания.
2. Проверить Ctrl + Shift + стрелка/буква в редакторе: выполняется действие редактора, раскладка остаётся прежней.
3. Удерживать сочетание, затем отпустить любую его клавишу: одно переключение. Отпускание остальных клавиш не должно переключать повторно. Для Alt + Shift проверить несколько нажатий и отпусканий Shift при удержании Alt, затем наоборот: каждое отпускание переключает. Проверить отмену кликом и прокруткой до отпускания.
4. Добавить два сочетания, изменить и удалить записи, попробовать сохранить дубликат. Отменить запись через Esc и переключением окна. После перезапуска проверить сохранение списка, при обновлении — перенос старого сочетания. Проверить пересекающиеся сочетания на двойное срабатывание и чередование сочетаний с зажатым общим модификатором.
5. Выбрать две раскладки из трёх, удалить одну в macOS, проверить предупреждение и отсутствие переключения на неотмеченную.
6. Проверить паузу, сон/пробуждение и Secure Keyboard Entry в Terminal. Выключить защищённый ввод и проверить восстановление.
7. Включить автозапуск, проверить его в настройках macOS; отключить, если он не нужен.
8. Несколько раз быстро переключить раскладку, затем повторить после переключения штатным сочетанием macOS и при открытом меню LayoutSwitch. При заметной задержке проверить журнал `SwitchLatency`.
9. При полном пропуске переключения проверить категории `Shortcut` и `Monitoring`. Повторить нажатие отдельно после отпускания всех клавиш и остановки прокрутки, затем сравнить с переключением во время быстрого набора.

Тесты покрывают логику без генерации глобальных событий. Разрешения, реальную доставку аппаратных событий, особенности IME и вход в систему нужно проверять на используемом Mac.

## Удаление

Если приложение установлено через Homebrew, сначала отключите автозапуск в настройках приложения, затем выполните:

```sh
brew uninstall --cask lukdut/layoutswitch/layoutswitch
```

Настройки сохранятся. Чтобы удалить и настройки, используйте вместо этой команды `brew uninstall --cask --zap lukdut/layoutswitch/layoutswitch`. После удаления приложения ненужный tap можно отключить командой `brew untap lukdut/layoutswitch`.

При ручной установке:

Отключите автозапуск в настройках приложения, выберите «Завершить LayoutSwitch» и удалите `.app`. При необходимости удалите LayoutSwitch из списка «Мониторинг ввода» в системных настройках.
